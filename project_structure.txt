[1] 프로젝트 개요
--------------------------------------------------------------------------------
- 프레임워크: Django 6.1.1 (Python 3.13 권장)
- 목적: 스포츠지도자 자격 취득 현황, 기관·운영 프로그램 현황, 신청 현황
  데이터를 업로드/분석하고, 사용자에게 맞춤형 기관·자격 추천을 제공하는
  데이터 분석 MVP.
- 부가 기능: 지역 커뮤니티 게시판(community), 단기 대타 구인구직
  게시판(substitutes)
- DB: SQLite (db.sqlite3), ORM: Django ORM
- 데이터 처리: pandas, openpyxl (CSV/XLSX 업로드), requests + BeautifulSoup
  (KSPO 외부 사이트 크롤링)
- 기본 언어/시간대: ko-kr / Asia/Seoul

[3] 도메인 모델 (models.py) 요약
--------------------------------------------------------------------------------

[3-1] app (analytics/recommendations) 앱
  - UploadBatch          : CSV/XLSX 업로드 이력 (미리보기→검증→저장/실패 상태 관리)
  - Institution          : 기관 정보 (이름/지역 정규화, 유일 제약)
  - CanonicalSport       : 자격 종목 taxonomy 기준값 (프로그램 매칭의 기준)
  - Program              : 기관별 운영 프로그램 원본 + 종목 매칭 결과(match_grade 등)
  - ProgramCleanup       : Program을 건드리지 않고 1:1로 만드는 "정리 결과"
                           (운영중/종료/미확인, 사용 가능 여부, 제외 사유)
  - QualificationAggregate: 연도·지역·종목·등급별 자격 취득 집계
  - ApplicationStatus    : 프로그램별 신청 현황 (신청률/수요상태 계산 프로퍼티,
                           is_synthetic으로 합성 데이터 여부 구분)
  - ExamSchedule / ExamScheduleFetchStatus : KSPO 연간일정계획 캐시 + 갱신 상태

[3-2] community 앱
  - Post    : 게시글 (카테고리: 자유/시험정보/자료실/Q&A, 닉네임+비밀번호 해시 인증)
  - Comment : 댓글 (게시글 FK, 닉네임+비밀번호 해시)

[3-3] substitutes 앱
  - PhoneIdentity   : PASS 인증 전화번호의 해시 기반 신원 (원문 번호 미저장)
  - CenterContact   : 휴대폰 인증을 마친 센터 담당자 (공고 등록 주체)
  - Posting         : 단기 대타 공고 (종목/일시/지역/급여/모집인원/상태)
  - Application     : 공고에 대한 지원 (전화번호 신원 기준 중복 지원 방지)
  - ReputationRecord: 대타 완료 후 평판 기록 (노쇼/컴플레인/긍정태그,
                      삭제 대신 is_hidden 처리로 감사 추적 보존)

[4] URL 라우팅 / 화면 흐름
--------------------------------------------------------------------------------
main/urls.py (최상위)
  /admin/            → Django 관리자
  /substitutes/...   → substitutes.urls
  /community/...     → community.urls
  /(기타 전체)...     → app.urls   (app_name='analytics')

app.urls (analytics) 주요 경로
  /                              → recommendations 시작 화면으로 리다이렉트
  /dashboard/                    → dashboard(): 전체 통계 요약
  /recommendations/              → recommendation_start(): 자격 보유/미보유 분기 선택
  /recommendations/licensed/(+results/)      → 자격 보유자 기관 추천 폼/결과
  /recommendations/unlicensed/(+results/)    → 자격 미보유자 자격 방향 추천 폼/결과
  /recommendations/qualifications/<pk>/      → 추천 자격 상세
  /upload/, /upload/<id>/mapping/, /upload/<id>/errors.csv → 데이터 업로드 3단계
  /instructors/, /exam-info/, /programs/, /current-programs/,
  /institutions/<pk>/, /applications/, /demand-supply/     → 각종 통계/조회 화면

community.urls
  /               → post_list      (게시글 목록)
  /posts/new/     → post_create
  /posts/<pk>/    → post_detail
  /posts/<pk>/edit/, /delete/            → post_edit / post_delete
  /posts/<pk>/comments/<id>/delete/      → comment_delete

substitutes.urls
  /                                       → posting_list (공고 목록)
  /postings/new/                          → posting_create
  /postings/<pk>/                         → posting_detail
  /postings/<pk>/apply/                   → application_apply
  /postings/<pk>/manage/<token>/          → applicant_manage (담당자 전용, 토큰 인증)
  /postings/<pk>/manage/<token>/applications/<id>/evaluate/ → application_evaluate

[10] 데이터 흐름 요약 (핵심 파이프라인)
--------------------------------------------------------------------------------
  1) 원본 CSV/XLSX (data/) 업로드
        → UploadBatch (미리보기/검증)
        → Institution / Program / QualificationAggregate 저장
  2) match_program_sports 실행
        → sport_matching.py가 sport_matching_rules.json 규칙으로
          Program.matched_sport(CanonicalSport) 자동 매칭
  3) clean_program_data 실행
        → program_cleanup.py가 program_cleanup_rules.json 기준으로
          ProgramCleanup(운영상태/사용가능여부/제외사유) 생성
  4) generate_demo_data 실행
        → ApplicationStatus 합성 신청 현황 생성 (is_synthetic=True)
  5) 사용자가 /recommendations/ 접근
        → recommendations.py의 점수 로직으로 Institution 또는
          CanonicalSport(자격 방향) 추천, 세션에 최소 입력값만 저장
  6) 대시보드/통계 화면(dashboard, programs, demand_supply 등)에서
        analytics.py의 summary()/sport_analysis()로 집계 시각화
