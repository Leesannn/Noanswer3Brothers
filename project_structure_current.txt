[1] 프로젝트 개요
--------------------------------------------------------------------------------
- Django 6.1.1 기반 웹 프로젝트이다.
- 스포츠지도자 자격 취득 현황, 기관별 프로그램, 신청 현황을 SQLite DB에 저장하고
  대시보드·통계·추천 서비스에서 조회한다.
- CSV/XLSX는 데이터 입력 수단이다. 평상시 웹 페이지는 CSV가 아니라 db.sqlite3를
  조회한다.
- 주요 앱은 analytics, recommendations, community, substitutes 네 개이다.
- 기본 언어/시간대는 ko-kr / Asia/Seoul이다.

[4-1] analytics/models.py: DB 모델
--------------------------------------------------------------------------------
UploadBatch
- CSV/XLSX 업로드 이력과 처리 상태를 저장한다.
- 원본 파일명, 데이터 종류, 인코딩, 행 수, 성공/실패/중복 수, 컬럼 매핑,
  미리보기와 오류 내용을 기록한다.
- 웹 업로드 파일은 처리 완료 후 임시 파일이 삭제된다.

Institution
- 기관명, 지역, 주소, 기관 유형을 저장한다.
- 정규화된 기관명 + 정규화된 지역 조합이 고유하다.

CanonicalSport
- 자격 종목의 기준 taxonomy이다.
- 프로그램 종목을 하나의 기준 종목으로 연결할 때 사용한다.

Program
- 기관에서 운영하는 프로그램 원본 정보를 저장한다.
- 기관, 프로그램명, 종목, 대상, 요일, 시간, 기간, 정원, 상태 등을 가진다.
- source_key가 같은 데이터는 갱신하고 다르면 새 행으로 추가한다.
- matched_sport와 match_* 필드에 자동 종목 매칭 결과를 저장한다.

DataSource
- 프로그램마다 반복되던 원본 파일명을 한 번만 저장하는 출처 사전이다.

ProgramMatchPayload
- 프로그램마다 반복되던 자동 매칭 규칙·후보 JSON을 고유 묶음으로 저장한다.

ProgramCleanup
- Program과 1:1로 연결되는 정리 결과이다.
- 정리된 이름, 운영 상태, 사용 가능 여부, 제외 사유와 판단 근거를 저장한다.

ProgramCleanupDetail
- 반복되는 정리 근거 문장과 적용 규칙을 고유 묶음으로 저장한다.

QualificationAggregate
- 연도·지역·종목·자격 종류·등급별 자격 취득 집계이다.
- 원본 파일명도 고유성 판단에 포함된다.

ApplicationStatus
- 프로그램별 기준일의 정원, 신청 인원, 대기 인원을 저장한다.
- is_synthetic으로 실제 데이터와 시연용 생성 데이터를 구분한다.

ExamSchedule
- KSPO 시험 일정 캐시이다.

ExamScheduleFetchStatus
- 시험 일정별 최근 갱신 성공·확인 시각과 오류를 저장한다.


[4-2] analytics/services/importers.py: CSV/XLSX 가져오기 핵심
--------------------------------------------------------------------------------
주요 상수
- FIELD_LABELS
  프로그램 내부에서 취급하는 전체 입력 필드와 사용자 표시 이름이다.
- REQUIRED_FIELDS
  데이터 종류별로 반드시 CSV 컬럼을 연결해야 하는 내부 필드이다.
- ALIASES
  서로 다른 CSV 컬럼명을 같은 내부 필드로 자동 연결하기 위한 별칭이다.

예시
  신청인원 / 접수인원 / 등록인원
      ↓ 자동 컬럼 매핑
  ApplicationStatus.applicants

주의: 별칭 여러 개의 값을 합산하는 것이 아니다. 한 CSV에서 일치하는 컬럼 하나를
선택해 applicants에 연결한다.

주요 함수
- detect_encoding()       UTF-8-SIG, UTF-8, CP949, EUC-KR 인코딩 탐지
- xlsx_sheets()           XLSX 시트 목록 확인
- iter_table()            CSV 또는 XLSX의 헤더와 행 읽기
- detect_dataset_type()   qualification/program/application 자동 판별
- suggest_mapping()       ALIASES를 이용한 컬럼 연결 자동 제안
- preview()               행 수, 빈값 수, 앞 20행과 매핑 제안 생성
- validate_mapping()      필수 필드 매핑과 존재하지 않는 컬럼 검사
- _source_key()           여러 값을 SHA-256으로 묶어 고유 식별키 생성
- import_batch()          데이터 종류에 맞는 저장 함수로 분기
- _import_qualifications() 자격 취득 데이터 저장
- _import_programs()       기관·프로그램 데이터 저장
- _import_applications()   신청 현황 데이터 저장

필수 컬럼 매핑
- qualification: acquisition_date, sport, qualification
- program: institution, program
- application: program, capacity, applicants

선택 필드는 FIELD_LABELS에는 있지만 REQUIRED_FIELDS에는 없는 항목이다.
선택 필드가 매핑되지 않았을 때의 저장 형태
- 문자열 필드: 주로 빈 문자열 ''
- 날짜·시간·숫자 필드: 주로 NULL
- 기본값이 있는 필드: 해당 기본값(예: 프로그램 상태 '운영')

오류 처리
- 기본값 allow_invalid=False
  한 행이라도 검증 오류가 있으면 ImportValidationError가 발생한다.
  import_batch()는 transaction.atomic이므로 해당 가져오기 전체가 롤백된다.
- allow_invalid=True
  오류 행을 제외하고 유효한 행만 DB에 저장한다.

DB 저장 방식
- bulk_create(..., update_conflicts=True)를 사용한다.
- 동일한 고유키: 기존 행 UPDATE
- 다른 고유키: 새 행 INSERT
- 새 파일에서 빠진 기존 행: 자동 삭제하지 않고 DB에 계속 유지
- 따라서 현재 가져오기 방식은 전체 교체가 아니라 누적 + 일부 갱신 방식이다.

[9] CSV/XLSX부터 웹 화면까지의 흐름
--------------------------------------------------------------------------------
1. 웹 /upload/ 또는 import_sports_file 명령으로 파일 선택
2. iter_table()이 CSV/XLSX를 읽음
3. detect_dataset_type()이 데이터 종류 판별
4. suggest_mapping()이 ALIASES로 컬럼 매핑 제안
5. validate_mapping()이 필수 매핑과 실제 헤더 확인
6. normalizers.py가 문자열·지역·종목·기관 값을 정규화
7. _import_*()가 고유키를 만들고 SQLite에 INSERT 또는 UPDATE
8. 웹 업로드인 경우 처리 완료 후 임시 원본 파일 삭제
9. 이후 일반 웹 요청은 CSV가 아니라 db.sqlite3를 조회

요약
  CSV/XLSX
      ↓ 가져오기 시에만 읽음
  정규화·검증·고유키 생성
      ↓
  db.sqlite3
      ↓ 평상시 웹 요청
  대시보드·현황·추천·커뮤니티·대타 서비스
